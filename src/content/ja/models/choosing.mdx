日常的なドキュメントの作成・編集は、**GPT-6 Lunaから始めて**ください。既存ドキュメントの文章・表・複数箇所を修正する作業には、**Claude Haiku 5.5も十分に活用できます**。依頼した内容が正しく保存されたか、作業時間が適切かを基準に選びます。

## 作業に合わせて選ぶ

| 作業 | 最初に試すモデル | 選択基準 |
| --- | --- | --- |
| 提供した資料から短いドキュメントの下書きを作る | **GPT-6 Luna** | 既定モデルで下書きを作り、事実と不足項目を確認します。 |
| 文章の変更、表の修正、複数ドキュメントの指定箇所の編集 | **GPT-6 Luna · Claude Haiku 5.5** | 対象と期待する結果が明確なら、この2モデルから始めます。どちらも該当する編集を完了しました。 |
| 短い編集の待ち時間を減らす | **Claude Sonnet 5.5も比較** | 精密な編集の測定中央値は約11秒でした。同じ依頼で速度と使用量を比較してください。 |
| 資料を読み、ドキュメント全体の構成を作る | **Lunaから始め、必要ならGPT-6.1 Solと比較** | セクションの漏れや説明のつながりが不足するとき、同じ資料で別の結果を比較します。 |
| 長い資料の解釈、複雑な分析・レビュー | **Sonnet・Sol・Claude Opus 5.5を比較** | 資料の長さ、説明の深さ、引用の正確性で判断します。モデル変更後も結果をレビューしてください。 |
| 別のOpenAIモデルの結果を確認 | **GPT-5.6 Terra** | 同じ資料と依頼で表現・構成・作業時間を比較できます。 |

## ドキュメント作業の性能

2026年10月の作業記録に基づき、同じ生成・編集の依頼で、読み取り・生成・編集・探索ツールが成功応答を返した割合と保存結果を比較しました。精密な編集とは、**部分修正、表の修正、複数ドキュメントの指定箇所の修正**を指します。

| モデル | 文書ツール呼び出し成功率 | 精密編集の完了率 | 編集時間の中央値 |
| --- | --- | --- | --- |
| Claude Opus 5.5 | 100% | 100% | 約21秒 |
| Claude Sonnet 5.5 | 90.9% | 100% | 約11秒 |
| Claude Haiku 5.5 | 100% | 100% | 約15秒 |
| GPT-6.1 Sol | 100% | 100% | 約20秒 |
| GPT-5.6 Terra | 94.1% | 100% | 約24秒 |
| GPT-6 Luna | 100% | 100% | 約17秒 |

呼び出し成功率は、**個々の呼び出しが正常に処理された割合**です。編集完了率は、**保存されたドキュメントが依頼の修正条件を満たした割合**です。呼び出しでエラーが出ても、後続処理で編集を完了できる場合があります。時間は編集開始から実行完了までの観測値で、文書の長さ・検索範囲・サーバーの状態によって変わります。短い文書作業の観測値であり、すべての作業の成功を保証するものではありません。

**小さな編集では、LunaとHaikuでも依頼した結果を得られました。** モデル変更の基準は、実際の結果の漏れ、根拠の正確性、所要時間です。新規作成では、提供していない事実が追加されていないか確認してください。

## ドキュメント自動化に合わせて選ぶ

ドキュメント自動化は、**ソースの読み取り → 文書作成 → 変更の反映 → 関連文書の照合**に分けて選びます。小さな編集の速度だけで、プロジェクト全体の更新性能を判断することはできません。

| 作業 | 自動化で扱う内容 | モデル選択と結果の確認基準 |
| --- | --- | --- |
| **API文書の生成** | エンドポイント、認証、リクエスト・レスポンス、エラー、制限値をコードから読み、下書きを作成 | **Lunaから始めます**。LunaとHaikuの生成結果でも主要API項目が作成されました。コードとテストが説明を裏付けるか確認します。 |
| **プロジェクトWikiの生成** | 実行方法、モジュールの役割、データフロー、運用確認事項を複数文書に整理 | 先に必須の目次を決めます。構成のつながりや根拠が不足する場合は**Sol・Sonnet・Opus**を比較します。Wiki生成記録には、Solが文書作成条件と引用根拠の確認をともに満たした結果があります。 |
| **コード変更後の更新** | 追加APIや変更された既定値・ポリシーを関連文書に反映 | プロジェクトの**ドキュメント生成モデル**を使います。編集した文書数より、必要なすべての文書に変更が反映されたか確認します。 |
| **削除・名前変更の反映** | 廃止機能の説明・例を整理し、ソースのパスや文書名を更新 | 本文と併せて名前・リンク・例も確認します。説明が不足する場合はモデルを比較し、保存・ツールの失敗はまず作業のエラーを確認します。 |
| **文書に無関係なコード変更** | 文書に影響しない変更を区別 | 不要な本文修正をせず、既存内容を維持するか確認します。修正量が多いほど良い結果とは限りません。 |
| **連続変更の処理** | 順番に入った変更を最後のコード状態に合わせて反映 | 中間値が残らず、概要と詳細文書が同じ最終値を説明するか確認します。 |

**下書きと部分修正はLuna・Haikuから活用し、全体構成や根拠の解釈が不足するときに別のモデルを比較**してください。自動化モデルは、作成する文書の種類と実際の反映結果で選びます。設定は[ドキュメントプロジェクトの作成](/ja/guides/doc-projects)、変更反映は[修正案のレビューと反映](/ja/guides/review-proposals)を参照してください。

## ドキュメントの整合性を合わせる

整合性は、**文書とコードが合うか**、**関連文書が同じ事実を説明するか**、**引用が主張を裏付けるか**を併せて確認する基準です。ツールの正常実行や文書の保存とは別に確認します。

| 確認対象 | 良い結果の基準 |
| --- | --- |
| **既定値・ポリシー・上限** | 概要、APIレファレンス、運用文書が現行コードの同じ値を説明します。 |
| **削除された機能** | 現行機能として残る説明・例・リンクがなく、必要な変更案内があります。 |
| **名前とパス** | 保存された文書名、本文の見出し、ソースのリンクが同じ現在の名前を使います。 |
| **リクエスト・レスポンス・エラー** | コードとテストで確認した動作が説明や例と一致します。 |
| **引用根拠** | パスと行番号が合うだけでなく、原文が実際に主張を裏付けます。 |
| **既存のチームの説明** | コード変更に無関係な手動作成内容や運用説明を維持します。 |

整合性を合わせるときは、**変更した事実と確認する文書一覧を併せて指定**してください。例えば「既定limitの変更を概要・APIレファレンス・運用ガイドで照合し、異なる値と根拠のない説明を整理して」と依頼します。まずLuna・Haikuで範囲の明確な修正を行い、資料の解釈や文書全体のつながりが不足するときに別のモデルと比較してください。選択基準は**変更の漏れがないことと根拠の正確性**です。

## モデルを変更するタイミング

- **希望する箇所が修正されない場合**は、文書と修正位置、変更する内容と維持する内容を指定します。それでも不十分なら、同じ依頼で別のモデルを比較します。
- **長い文書の構成が不足する場合**は、先に目次と必須項目を決め、セクションごとに作成します。説明や分析が不足するとき、Sonnet・Sol・Opusの結果を比較します。
- **コード変更を複数文書に反映する場合**は、概要・レファレンス・運用文書の値と例を併せて確認します。大きなモデルでも全体の反映は保証されません。
- **出典が重要な場合**は、回答と引用元を照合します。リンクが開くだけでなく、実際の説明を裏付けるか確認してください。

## 思考の強度を選ぶ

短い下書きや指定箇所の修正は、**オフ**または対応する低い段階から始めます。複数資料の比較や深い説明が必要なときに強度を上げ、結果を比較してください。強度を上げると時間と使用量が増える場合があります。無料プランでは**オフ**に固定されます。

## ワークスペースの既定モデルを決める

オートメーションとドキュメント生成は、チャットとは別にワークスペースのモデル設定を使います。

<Screenshot name="settings-workspace" alt="ワークスペースの一般設定にあるデフォルトAIモデルとドキュメント生成モデルの選択欄" />

- **デフォルトAIモデル** — このワークスペースのオートメーションに使います。日常的な文書作業はGPT-6 Lunaから始め、実際の結果と使用量に合わせて調整してください。
- **ドキュメント生成モデル** — プロジェクト作成と自動更新に使います。設定がない、または無効な場合はGPT-6 Lunaを使います。文書の種類と実際の生成結果で選びます。

対応モデルとコンテキストは[モデルの概要](/ja/models/overview)、使用量の管理は[使用量とAI予算](/ja/models/usage)を参照してください。
