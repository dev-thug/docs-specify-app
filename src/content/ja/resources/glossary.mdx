Specifyの製品とドキュメントでよく使われる用語です。

| 用語 | 意味 |
| --- | --- |
| **ワークスペース** | チームがドキュメント・会話・意思決定・コードの記録と、メンバー、接続ツールを共有する単位。データが分離される境界です。 |
| **ノード** | ワークスペースの中心となるコンテンツの単位。ドキュメント、フォルダ、エージェントのルールはすべてノードです。 |
| **ドキュメントプロジェクト** | GitHubリポジトリを根拠に開発ドキュメントを作成・維持する単位。フォルダ、ソース、スキル、自動化設定をまとめます。 |
| **ソース** | ドキュメントプロジェクトが根拠とするGitHubリポジトリとブランチ。 |
| **ドキュメントスキル** | エージェントがドキュメントを生成するときに従う作成規律。 |
| **補助スキル** | ドキュメントスキルを補助する参考手順。最大5個まで選択できます。 |
| **増分更新** | コードの変更分だけを反映してドキュメントを更新する方式。自動更新に対応しています。 |
| **全体再生成** | 毎回ドキュメント全体を作り直す方式。自動更新には対応していません。 |
| **修正案** | コード変更に合わせてドキュメントを更新するための提案。変更の根拠と修正前後を含みます。 |
| **push で実行** | ソースブランチにコードがpushされたときに、ドキュメントの修正案を用意するトリガー。 |
| **スタイルガイド** | ドキュメントに適用するMarkdownの作成ルール。プロジェクトのガイドがワークスペースのガイドより優先されます。 |
| **インボックス** | バックグラウンドタスクの進行状況と結果が集まる場所。 |
| **スレッド** | エージェントとの会話の単位。 |
| **デイリーブリーフィング** | ワークスペースの変更、ドキュメントの陳腐化の通知、おすすめの作業をまとめた日次サマリー。 |
| **RAG** | 検索拡張生成。AIが回答したりドキュメントを書いたりする前に、ワークスペースの資料を検索して根拠とする方式。[ワークスペースRAG](/ja/knowledge/rag)を参照。 |
| **インデックス化** | RAG検索のために、ドキュメントとファイルを断片（チャンク）に分けて保存する処理。ドキュメントを編集したりファイルをアップロードしたりすると、再びインデックス化されます。 |
| **規格文書ライブラリ** | IEC 62304、ISO 14971などの規格を条項単位で検索するナレッジソース。[規格文書ライブラリ](/ja/knowledge/standards)を参照。 |
| **[GAP]** | 規格や資料で裏付けられない内容に、エージェントが付ける印。人が確認する必要があります。 |
| **思考の強度** | モデルが回答する前に推論する深さ。オフ、低、中、高、エクストラ、最大から選びます。 |
| **コネクター** | GitHub、Notion、Slackなどの外部サービスを接続し、エージェントが読み取りや作業を行えるようにする連携。 |
| **プラグイン** | 複数のスキルをまとめて一度にインストールするパッケージ。例：medical-device-docs。 |
| **オートメーション** | 決められたスケジュールでエージェントがプロンプトを実行するように作成したルーティン。 |
| **MCP** | Model Context Protocol。AIエージェントを外部のツールやデータに接続するためのオープン標準。 |
| **Specify MCP** | Claude Code・Codexなどの外部コーディングエージェントに、ワークスペースの文脈を提供するMCPサーバー。 |
| **MCPトークン** | 外部エディターがSpecify MCPに認証するときに使う、ワークスペース単位のトークン。既定の権限は読み取り専用です。 |
