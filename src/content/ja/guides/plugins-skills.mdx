**スキル**は、エージェントが特定の作業を行うときに従う手順と利用条件です。**プラグイン**は、複数のスキル（とエージェント・MCPサーバー・イベントフック）をまとめたパッケージで、公式マーケットプレイスから一度にインストールできます。

## プラグインをインストールする

**設定** → **AIエージェント** → **プラグイン**で、公式マーケットプレイスを見て回ります。

<Screenshot name="settings-plugins" alt="プラグインの画面。カタログとインストール済みのタブ、カテゴリのフィルター、doc-quality、specify-docs、medical-device-docsなどのおすすめプラグインの一覧がある" />

1. **カタログ**タブで、カテゴリ（生産性、コミュニケーション、開発、デザイン、マーケティング、財務、法務）で絞り込むか、検索します。
2. プラグインを押して、**含まれるコンポーネント**と**要求される権限**を確認します。
3. **+**または**インストール**を押します。インストールしたプラグインは**インストール済み**タブで確認でき、**削除**することもできます。

インストールしたスキルは、このワークスペースのエージェントが使用します。

### 主な公式プラグイン

| プラグイン | 説明 |
| --- | --- |
| **specify-docs** | Specify公式のドキュメントスキル |
| **doc-quality** | ドキュメントの品質レビュースキルのセット |
| **eng-quality** | 障害の振り返り・技術ドキュメントの品質など、エンジニアリング品質のスキル |
| **medical-device-docs** | 医療機器ソフトウェアのドキュメントパック（IEC 62304・ISO 14971）— コードと規格の根拠に基づく |
| **productivity-meetings** | 議事録の整理・アクションアイテムの抽出など、会議の生産性スキル |
| **marketing-content** | コンテンツブリーフ・キャンペーンコピーなど、マーケティングコンテンツのスキル |

**medical-device-docs**は、規格の条項を検索して引用しながらドキュメントを書きます。[規格文書ライブラリ](/ja/knowledge/standards)を参照してください。

### GitHubから取り込む

プラグインの画面の**追加** → **GitHub リポをインポート**で、GitHubリポジトリにあるプラグインを取り込めます。**GitHub リポ URL**と、必要に応じて**ブランチ・タグ・コミット**を入力します。

## スキルを管理する

**設定** → **ツールとスキル** → **スキル**で、ワークスペースのスキルを確認します。

<Screenshot name="tools-skills" alt="スキルの画面。すべて、マイスキル、エージェント学習、プラグインのタブと、使用中のスキルのカード一覧がある" />

- **すべて・マイスキル・エージェント学習・プラグイン**のタブで、出どころごとに絞り込みます。
- **追加**で新しいスキルを作成します。名前、説明、バージョン、タグとともに、**手順**（本文）をMarkdownで書きます。
- よく使うスキルはピン留めして、一覧の先頭に置きます。
- スキルは**SKILL.md をエクスポート**でファイルとしてダウンロードできます。

<Tip>
  よいスキルは、「いつ使うのか」と「どの順序で行うのか」が明確です。説明には利用条件を、手順にはステップと完了基準を書いてください。
</Tip>

## エージェント学習

エージェントは、会話から学んだ内容を**メモリ**と**スキル**として自動で保存します。**設定** → **AIエージェント** → **エージェント学習**で、**アクティビティ**、**メモリ**、**スキル**、**キュレーター履歴**を確認し、不要な記憶を削除したり、スキルの変更を以前のバージョンに戻したりできます。

## ドキュメントプロジェクトでスキルを使う

[ドキュメントプロジェクト](/ja/guides/doc-projects)の作成時に選ぶ**ドキュメントスキル**も、同じスキルです。インストール済みのドキュメントスキルがない場合は、マーケットプレイスで探すか新しく作成でき、補助スキルは最大5個まで一緒に使えます。
