Specify는 코드 변경을 읽고, 고쳐야 할 개발문서를 찾아, 검토할 수 있는 수정안으로 연결합니다. 문서를 직접 쓸 여력이 없는 팀도 GitHub 저장소를 연결하는 것만으로 코드와 함께 움직이는 개발문서를 유지할 수 있습니다.

Specify를 활용하는 방법은 크게 두 가지이며, 팀의 상황에 따라 함께 사용할 수 있습니다.

|  | 문서 자동화 | Specify MCP |
| --- | --- | --- |
| **무엇인가** | GitHub 저장소를 근거로 개발문서를 생성하고, 코드 변경에 맞춰 수정안을 준비하는 워크스페이스 기능 | Claude Code·Codex·Cursor 같은 코딩 에이전트가 팀 워크스페이스의 문서와 맥락을 읽도록 연결하는 MCP 서버 |
| **적합한 용도** | API·아키텍처·온보딩 문서를 코드와 동기화 | 에이전트에 프로젝트 배경을 매번 붙여 넣지 않고 팀 맥락 위에서 작업 |
| **시작하기** | [빠른 시작](/ko/quickstart) | [MCP 개요](/ko/mcp/overview) |

  <Card icon="pr" title="근거가 있는 수정안">코드가 바뀌면 영향을 받는 문서를 찾아 변경 이유와 수정 전후를 담은 수정안을 준비합니다.</Card>
  <Card icon="message" title="팀 맥락으로 답변">문서·결정·코드 기록을 근거로 "왜 이렇게 만들었는지", "어디에 있는지"에 답합니다.</Card>

</Note>

## 주요 활용 사례

- **API·개발 문서 최신화** — API 코드가 있는 저장소를 연결해 두면, 엔드포인트·요청 스키마·응답 필드가 코드와 어긋날 때마다 수정안이 준비됩니다. 검토할 항목은 [API 문서 최신화](/ko/guides/api-docs)를 참고하세요.
- **개발자 온보딩 문서** — 저장소 구조와 실행 방법을 근거로, 새 팀원이 첫날 로컬 실행까지 도달하는 문서 초안을 만듭니다. 코드에 없는 팀 절차는 사람이 보완합니다. [온보딩 문서 생성](/ko/guides/onboarding-docs)을 참고하세요.
- **팀 지식 검색** — 문서를 뒤지거나 동료를 붙잡지 않고, 워크스페이스의 문서와 자료를 근거로 답을 얻습니다. [AI에게 질문하기](/ko/guides/ask-ai)를 참고하세요.

보안 질문서 답변, 프로젝트 인수인계, 고객 안내문처럼 개발 업무 밖의 사례까지 포함해 [활용사례 둘러보기](/ko/guides/use-cases)에서 준비할 자료와 만들어지는 결과물을 사례별로 확인할 수 있습니다.
