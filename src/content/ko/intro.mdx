Specify는 코드를 **설계도와 자연어 기능 문서**로 보여 주는 워크스페이스입니다. 코딩 에이전트가 만든 결과를 이해하고, 의도와 다른 부분을 리뷰하고, 개선할 내용을 다시 에이전트가 읽을 수 있는 문서로 남기세요.

## 설계도로 코드 파악하고 리뷰하기

저장소를 근거로 아키텍처, 기능 흐름, API 동작을 설명하게 하고 그 결과를 읽어 보세요. 구조와 동작을 의도한 설계 및 요구사항과 대조하며 리뷰할 수 있습니다.

<Screenshot name="architecture-document" alt="저장소 구조와 처리 흐름을 정리한 Specify 프로젝트 문서" caption="기능 설명과 소스 경로를 함께 읽으며 구현을 확인합니다." />

1. **파악** — 저장소를 연결하고 프로젝트 개요와 주요 동작을 문서로 만듭니다.
2. **리뷰** — 문서와 캔버스를 보며 의존 방향과 기능 흐름을 요구사항에 맞춰 검토합니다.
3. **교정** — 채팅에서 개선 내용을 문서로 정리하고 코딩 에이전트가 MCP로 읽어 수정하게 합니다.
4. **재확인** — 저장소에 연결한 문서·캔버스의 갱신 결과를 다음 변경 뒤에 확인합니다.

<Note>저장소 변경의 자동 갱신은 **그 저장소에 연결한 문서·캔버스**에 적용됩니다. 에이전트가 내용을 직접 수정하고 저장합니다. 완료 후 변경 기록과 저장된 결과를 확인하세요.</Note>

## 인증 문서를 준비하기

인증 문서도 같은 자료에서 출발합니다. 제품 개요, 요구사항, 설계와 테스트 자료를 모으고, 확인된 사실과 부족한 근거를 나눠 초안을 작성하세요. [인증 문서 가이드](/ko/guides/medical-device-docs)에서 준비물과 검토 순서를 확인할 수 있습니다.

지원 분야와 전문가 검토가 필요하다면 [Specify Certify](https://certify.specify.app)를 확인하세요. 제출 자료는 전문가 검토로 완성하고, 인증과 적합성은 해당 평가 절차에서 확인합니다.

## 에이전트와 같은 맥락에서 작업하기

개선 문서를 코딩 에이전트가 직접 찾아 읽게 하세요. [Specify MCP](/ko/mcp/overview)를 연결하고 코딩 에이전트에 “Specify의 개선 문서를 읽고 이 내용에 맞춰 수정해 줘”라고 요청하세요. 문서를 검색하고 읽는 도구와 허용된 쓰기 도구는 [MCP 도구](/ko/mcp/tools)에서 확인할 수 있습니다.
