GitHub 저장소에서 첫 문서를 만들고, 설계도를 리뷰한 뒤 개선 내용을 남겨 보세요. 생성 결과는 저장소의 실제 구현과 대조하며 읽는 것이 좋습니다.

## 준비물

- Specify 계정과 워크스페이스
- Specify가 읽을 수 있도록 연결된 GitHub 저장소
- GitHub를 연결할 워크스페이스 관리 권한

사용 가능한 기능과 요금제는 [공식 요금제](https://specify.app/pricing)에서 확인하세요.

## 첫 문서 만들기

<Steps>
  <Step title="워크스페이스 홈 열기">
    로그인하고 사용할 워크스페이스를 고릅니다. 사이드바의 **홈**에서 시작합니다.

    <Screenshot name="workspace-home" alt="저장소에서 문서 만들기를 시작하는 워크스페이스 홈" />
  </Step>
  <Step title="저장소 선택하기">
    **GitHub 저장소로 문서 만들기**를 누릅니다. 처음이라면 **GitHub 연결**로 접근을 허용할 저장소를 선택하세요. 이미 연결돼 있다면 저장소 목록이 표시됩니다.

    <Screenshot name="github-repositories" alt="연결된 GitHub 저장소를 선택하는 화면" />
  </Step>
  <Step title="문서 생성 시작하기">
    분석할 저장소를 선택하고 **문서 만들기**를 누릅니다. 기본 브랜치의 코드를 읽는 요청이 채팅에서 시작되며, 한국어 UI에서는 한국어 문서를 요청합니다.
  </Step>
  <Step title="저장 결과 확인하기">
    채팅의 진행 상황을 확인하고 생성된 문서를 엽니다. 설명에 적힌 소스 경로, 주요 기능과 한계를 저장소와 대조합니다. 오류나 추가 질문이 있다면 같은 채팅에서 이어갑니다.
  </Step>
</Steps>

## 설계도와 개선 문서로 이어가기

채팅에 다음처럼 요청해 보세요.

> 이 저장소의 주요 구성요소와 호출 흐름을 아키텍처 캔버스로 만들어 줘. 문서에 적힌 소스 경로를 근거로 하고 추가 확인이 필요한 연결은 질문으로 남겨 줘.

설계도를 읽으며 의도와 다른 부분을 찾았다면, 근거와 원하는 동작을 적어 개선 문서로 정리합니다. 코딩 에이전트에 MCP로 이 문서를 읽게 한 뒤 실제 코드를 수정하게 할 수 있습니다.

<Note>코드가 바뀔 때 함께 갱신하려면 문서와 캔버스를 각각 해당 저장소에 연결하세요. 생성에 저장소를 사용한 것과 자동 갱신 연결은 구분됩니다. 자동 갱신은 연결된 콘텐츠를 직접 편집하므로, 완료 후 변경 기록을 확인합니다.</Note>
