Specify의 기능은 몇 가지 개념 위에 서 있습니다. 이 페이지에서 각 개념이 무엇이고 서로 어떻게 연결되는지 정리합니다.

## 전체 흐름

1. **워크스페이스**에 팀과 문서가 모입니다.
2. **문서 프로젝트**가 워크스페이스의 폴더와 GitHub **소스**를 묶습니다.
3. 에이전트가 **문서 스킬**을 따라 코드를 근거로 문서를 생성합니다.
4. 소스에 변경이 생기면 영향을 받는 문서에 **수정안**이 준비됩니다.
5. 팀은 **인박스**에서 진행 상황과 수정안을 확인하고, 코딩 에이전트는 **MCP**로 같은 맥락을 읽습니다.

## 워크스페이스

팀이 문서·대화·결정·코드 기록을 공유하는 단위입니다. 멤버와 역할, 연결된 도구, 요금제가 워크스페이스에 속합니다. 데이터는 워크스페이스 단위로 격리됩니다.

## 노드

워크스페이스의 핵심 콘텐츠 단위입니다. 문서, 폴더, 에이전트 규칙이 모두 노드이며 트리 구조로 정리됩니다. 문서 프로젝트는 특정 폴더 노드에 연결됩니다.

## 문서 프로젝트

GitHub 저장소를 분석해 아키텍처 문서, 온보딩 가이드, API 스펙 같은 개발문서를 만들고 유지하는 단위입니다. 문서 프로젝트는 다음을 가집니다.

- **소스** — 문서의 근거로 사용할 GitHub 저장소와 브랜치
- **문서 스킬** — 어떤 문서를 어떤 규율로 쓸지 정한 작성 절차
- **자동화 설정** — push 시 실행 여부, 기본 출력 폴더, 프로젝트 스타일 가이드

프로젝트 목록에서 각 프로젝트는 **최신**, **작성 중**, **확인 필요** 상태로 표시됩니다.

## 스킬

에이전트가 작업할 때 따르는 절차와 사용 조건입니다. 문서 프로젝트에서는 **문서 스킬**이 문서를 생성하는 작성 규율을 제공하고, **보조 스킬**이 문서 스킬을 돕는 참고 절차를 제공합니다. 보조 스킬은 최대 5개까지 선택할 수 있습니다.

스킬은 갱신 방식에 따라 두 가지로 나뉩니다.

| 방식 | 코드 변경 시 동작 |
| --- | --- |
| 증분 갱신 | 선택한 브랜치에 코드가 반영되면 문서 수정안을 자동으로 준비합니다. |
| 전체 재생성 | 자동 갱신을 지원하지 않습니다. 필요할 때 다시 생성합니다. |

## 수정안

코드 변경으로 문서를 고쳐야 할 때 Specify가 준비하는 제안입니다. 수정안에는 변경 근거와 수정 전후가 함께 담깁니다. 새 프로젝트는 자동 반영 없이 시작하며, 반영 방식은 프로젝트 설정과 적용 정책을 따릅니다. 자세한 내용은 [수정안 검토와 반영](/ko/guides/review-proposals)을 참고하세요.

## 인박스

백그라운드 작업의 진행 상황과 결과가 모이는 곳입니다. 문서 생성 화면을 닫아도 인박스에서 완료, 실패, 다시 시도 옵션을 계속 확인할 수 있습니다. 에이전트가 사용자의 답을 기다릴 때도 인박스와 스레드에서 이어갈 수 있습니다.

## 스레드

에이전트와 나누는 대화 단위입니다. 질문과 답변, 에이전트가 실행한 작업이 스레드에 기록됩니다. 문서 생성 중 에이전트가 질문하면 스레드를 열어 답하면 생성이 이어집니다.

## MCP

Model Context Protocol은 AI 에이전트를 외부 도구·데이터에 연결하는 개방형 표준입니다. Specify는 MCP 서버를 제공해 Claude Code·Codex·Cursor 같은 에이전트가 워크스페이스 권한이 허용한 범위 안에서 팀 문서를 검색하고 읽게 합니다. [MCP 개요](/ko/mcp/overview)를 참고하세요.
