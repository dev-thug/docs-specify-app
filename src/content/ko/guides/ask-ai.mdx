Specify 채팅은 워크스페이스 문서와 연결된 코드·외부 자료를 바탕으로 질문에 답하고 문서와 설계도를 만드는 작업 공간입니다. 질문할 때 대상과 원하는 결과를 함께 적으세요.

## 자료를 지정해 질문하기

입력창의 `@`로 문서나 저장소를 지정합니다. 예를 들어 “이 저장소의 로그인 구현과 현재 인증 문서를 대조해 차이를 알려 줘”처럼 요청할 수 있습니다. GitHub 저장소는 연결된 앱이 접근할 수 있어야 합니다.

```text
이 저장소의 주문 처리 흐름을 확인해 줘.
현재 문서와 다른 동작을 코드 근거와 함께 정리하고,
확인하지 못한 항목은 따로 남겨 줘.
```

## 답변에서 작업으로 이어가기

요약과 설명을 받은 뒤 문서 작성, 기존 문서 수정, 캔버스 생성도 요청할 수 있습니다. 저장할 위치와 변경 범위를 알려 주세요. 기존 문서를 고칠 때는 보존할 섹션을 지정하면 좋습니다.

작업 목록에서 코드 읽기와 문서 반영의 진행 상황을 각각 확인할 수 있습니다. 문서 반영이 완료되면 실제 결과물을 열어 저장된 내용을 확인하세요.

## 설계도를 그리며 대화하기

“이 흐름을 다이어그램으로 그려 줘”라고 요청해 구조를 시각화할 수 있습니다. 캔버스를 열면 하단의 **캔버스에 명령하기…**에서 같은 대화를 이어가며 배치, 라벨과 연결을 개선합니다. 도형이나 연결선을 선택하면 선택 항목도 요청의 맥락으로 전달됩니다.

[아키텍처 다이어그램과 캔버스](/ko/guides/canvas)에서 전체 구조 명령과 선택 영역 수정을 따라 해 보세요.

## 근거 확인하기

대화의 근거에서 어떤 자료를 참고했는지 확인합니다. 틀렸거나 부적절한 근거는 철회할 수 있으며, 철회한 근거는 이후 답변에 사용하지 않습니다. 원본이 바뀌거나 접근할 수 없게 된 근거도 상태가 달라질 수 있습니다.

중요한 결정에 쓰기 전에는 원문과 코드의 실제 동작을 대조하세요. 범위를 전부 읽지 못했다면 남은 범위를 명시하고 추가 확인을 요청합니다.

## 모델과 사고 강도

입력창의 모델 설정에서 현재 대화의 모델과 지원되는 사고 강도를 선택합니다. 응답 중에는 모델 변경이 잠깁니다. 더 높은 강도는 응답 시간과 사용량을 늘릴 수 있습니다. 모델별 측정 근거는 [모델 선택 가이드](/ko/models/choosing)를 참고하세요.

## 외부 서비스와 코딩 에이전트

[커넥터](/ko/guides/connectors)를 연결하고 AI 접근을 켜면 허용된 외부 자료를 함께 참고할 수 있습니다. IDE에서도 같은 팀 문서를 사용하려면 [Specify MCP](/ko/mcp/overview)를 연결하세요.
