의료기기 소프트웨어 문서는 코드에서 확인한 기능·구조와 제품·안전 판단을 구분해 준비합니다. Specify에서 초안을 관리하고 필요한 전문 검토를 연결하세요.

## 제품과 문서 범위 정하기

제품 버전, 사용 목적, 대상 사용자, 소프트웨어 범위, 현재 보유한 요구사항·설계·시험 자료를 준비합니다. 사용 목적, 안전 판단, 적용 규격은 제품 자료와 전문가 검토를 함께 근거로 정합니다. [Specify 인증 지원](https://certify.specify.app)에서 의료기기 소프트웨어의 문서 준비와 지원 범위를 확인할 수 있습니다.

## 코드 근거로 초안 만들기

저장소를 연결하고 채팅으로 구현된 기능과 아키텍처를 설명하도록 요청합니다. 이를 바탕으로 요구사항·설계 초안을 정리하고 근거 파일, 관련 항목, 미확인 내용을 남깁니다. 의존성 목록을 외부 소프트웨어 검토의 입력 자료로 활용하고, 각 의존성의 용도와 위험, 검증 근거를 담당자가 확인해 안전성 검토를 진행합니다.

## 보완과 변경 관리하기

요구사항, 설계, 시험 결과 사이의 연결과 빠진 근거를 담당자가 확인합니다. 부족한 내용은 확인할 질문과 개선 문서로 정리하고, 구현 변경은 코딩 에이전트가 MCP로 읽어 진행하게 할 수 있습니다. 저장소·브랜치가 연결된 문서와 캔버스는 push 후 직접 갱신될 수 있으므로 변경 결과와 문서 간 일관성을 검토하세요.

## 채팅 요청 예시

```text
대상 제품 버전의 소스와 기존 요구사항·설계·시험 자료를 읽어 줘.
코드에서 확인한 기능과 구조, 관련 파일, 문서 간 참조를 정리해 줘.
미확인 제품 정보와 누락된 근거는 질문으로 남겨 줘.
코드 분석을 안전성 검증 완료나 인증 적합 판정으로 표현하지 말아 줘.
```

<Note>Specify에서 초안과 변경을 관리한 뒤, 책임 있는 담당자와 전문가가 규제·안전 판단, 시험 수행과 제출 문서의 최종 검토를 진행합니다. 인증 취득과 심사 결과는 해당 심사 절차에서 결정됩니다. 실제 지원 문서와 전문 서비스 범위는 상담으로 확인하세요.</Note>
