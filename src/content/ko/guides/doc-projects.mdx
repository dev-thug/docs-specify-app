Specify는 GitHub 코드를 읽어 기능 문서와 아키텍처 설계도를 만들고, 완성된 문서·캔버스에 저장소를 연결해 이후 변경을 반영합니다. 먼저 필요한 결과물을 만들고 각 콘텐츠에 자동 갱신을 연결하세요.

## 시작하기 전에

[GitHub 연결](/ko/guides/github)을 완료하고 문서화할 저장소가 앱의 접근 범위에 포함돼 있는지 확인합니다. 문서를 저장할 워크스페이스와 폴더도 정합니다.

## 첫 문서와 설계도 만들기

1. 채팅에서 저장소를 선택하거나 `@`로 저장소를 지정합니다.
2. 기능, 대상 독자, 출력 형식을 구체적으로 요청합니다. 핵심 흐름부터 시작해 필요한 범위로 확장하세요.
3. 에이전트가 코드를 확인하고 문서나 캔버스를 저장하면 결과를 엽니다. 추가 질문이 오면 같은 대화에서 답합니다.

```text
이 저장소의 로그인 흐름을 코드로 확인해 줘.
진입점, 인증 처리, 데이터 저장, 오류 처리를 설명하는 문서와
구성 요소 사이의 관계를 보여 주는 아키텍처 설계도를 만들어 줘.
확인하지 못한 부분은 별도로 표시해 줘.
```

## 저장된 결과 확인하기

문서의 주장과 코드 근거를 대조합니다. 설계도에서는 구성 요소, 연결 방향, 외부 의존성을 확인하세요. 실행이 완료되면 저장된 내용을 검토하고, 누락된 범위는 같은 대화에서 보완을 요청합니다.

## 자동 갱신 연결하기

각 문서·캔버스의 **연결** → **연결 관리** → **이벤트 연결**에서 저장소를 체크합니다. 연결된 기본 브랜치의 다음 push부터 변경을 분석해 해당 콘텐츠를 직접 갱신합니다. 문서와 설계도 모두 최신 상태로 유지하려면 각각 연결합니다.

## 문서 묶음 확장하기

같은 저장소로 API 설명, 온보딩 가이드, 운영 절차 등 필요한 문서를 추가 요청하고 폴더로 정리합니다. 재사용할 작성 지침은 [스킬](/ko/guides/plugins-skills)로 관리합니다. 갱신 후에는 [결과 확인](/ko/guides/review-proposals)을 진행하세요.
