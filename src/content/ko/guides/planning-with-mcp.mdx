코드와 기획을 같은 맥락에서 리뷰하고, 합의한 개선 문서를 코딩 에이전트가 MCP로 읽게 하세요.

## 구조와 요구사항을 먼저 이해하기

GitHub 저장소를 연결한 뒤 채팅으로 주요 기능과 의존 관계를 설명하는 문서와 아키텍처 다이어그램을 요청합니다. 기획 문서도 함께 읽게 해 현재 구현, 의도한 동작, 아직 결정하지 않은 조건을 구분하세요.

## 리뷰를 개선 문서로 남기기

다이어그램과 기능 설명에서 바꿀 곳을 짚고 채팅으로 이유를 설명합니다. 기존 모듈을 재사용할지, 어떤 예외를 처리할지, 무엇을 테스트할지 합의해 별도의 개선 문서로 정리하세요. 같은 일을 하는 구성요소가 보이면 근거 코드를 확인한 뒤 통합 여부를 판단합니다.

## 구현과 다음 리뷰 연결하기

Claude Code나 Codex에 Specify MCP를 연결하고 개선 문서의 본문을 읽도록 요청합니다. 코딩 에이전트 쪽에서 구현과 테스트를 진행한 뒤 변경을 push합니다. 저장소·브랜치가 연결된 기존 문서와 캔버스는 해당 변경을 근거로 직접 갱신될 수 있습니다. 갱신 결과를 확인하고 남은 차이를 다시 리뷰하세요.

## 채팅 요청 예시

```text
예약 취소 기능의 현재 구현과 기획을 읽고 흐름과 예외를 설명해 줘.
취소 가능 시점과 화면 상태에서 결정할 점을 구분해 줘.
합의한 변경, 수정 범위, 수락 조건, 확인할 테스트를 개선 문서로 정리해 줘.
```

## 코딩 에이전트 요청 예시

```text
Specify MCP로 예약 취소 개선 문서의 본문을 읽어 줘.
현재 코드와 대조해 구현 계획을 정리하고, 합의한 범위를 구현하고 테스트해 줘.
문서에 없는 정책은 추측하지 말고 질문으로 남겨 줘.
```

<Note>기획이 바뀌면 구현 전 같은 문서를 다시 읽게 하세요. MCP는 코딩 에이전트가 호출해 읽는 방식입니다. Claude Code나 Codex에서 문서 읽기와 구현을 요청하고, Specify 채팅에서는 합의한 문서를 준비하세요.</Note>
