자동 갱신 후에는 실행 결과와 실제 문서·캔버스를 함께 확인합니다. 저장소 push로 시작된 작업은 연결된 콘텐츠를 직접 수정하며, 변경 이력과 실행 취소로 결과를 확인하고 되돌릴 수 있습니다.

## 갱신이 진행되는 과정

1. 연결된 저장소의 지정 브랜치에 push가 발생합니다.
2. 에이전트가 변경 차이, 브랜치의 현재 코드, 기존 콘텐츠를 대조합니다.
3. 관련된 사실이 달라졌다면 기존 문서나 캔버스를 갱신합니다. 관련 내용이 이미 최신이면 기존 내용을 유지할 수 있습니다.

연속 push가 발생하면 최신 실행이 이전 실행을 대체할 수 있습니다. 마지막 코드 상태가 결과에 반영됐는지 확인하세요.

## 실행 결과 열기

콘텐츠의 **연결**에서 저장소와 브랜치를 확인하고 **실행 기록**으로 인박스를 엽니다. 실행 결과에서 분석 범위와 후속 확인 항목을 살펴보고 실제 갱신 여부를 확인합니다. 읽지 못한 파일이나 도구 오류가 표시되면 해당 범위를 추가로 확인하세요.

## 내용 검토하기

- 바뀐 값, 기능 이름, API 예시가 현재 코드와 일치하는지 확인합니다.
- 문서와 설계도가 같은 구성 요소와 데이터 흐름을 설명하는지 대조합니다.
- 변경과 무관한 설명이나 사람이 작성한 내용이 보존됐는지 확인합니다.
- 근거를 읽지 못한 부분은 확인되지 않은 것으로 남기고 추가 분석을 요청합니다.

## 되돌리거나 잠시 멈추기

문서의 변경 이력을 확인하고 필요하면 변경을 되돌립니다. 특정 내용을 사람이 정리하는 동안에는 에이전트 편집 잠금을 사용할 수 있습니다. 잠금 중에도 사람은 계속 편집할 수 있으며 자동 갱신은 일시 중단됩니다.

향후 push를 반영하지 않으려면 **연결 관리** → **이벤트 연결**에서 저장소 체크를 해제합니다. [연결 관리](/ko/guides/automation-settings)를 참고하세요.
