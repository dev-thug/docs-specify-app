캔버스는 아키텍처를 **그리고, 설명하고, 에이전트와 함께 개선하는 작업 공간**입니다. 맘마(육아 앱)의 구성 요소와 데이터 흐름을 한 장으로 살펴보고, 화면 하단에 원하는 변경을 입력하며 설계를 발전시켜 보세요.

## 다이어그램과 캔버스 고르기

| 하고 싶은 일 | 시작할 곳 |
| --- | --- |
| 설명과 함께 구조·호출 순서를 보여 주기 | 문서나 채팅에서 다이어그램 요청 |
| 도형·텍스트·연결선을 직접 배치하며 설계하기 | 탐색기의 **새 캔버스** |
| 코드에서 현재 시스템 구조를 파악하기 | 연결한 저장소를 지정해 아키텍처 캔버스 요청 |
| 기존 설계를 대화하며 다듬기 | 캔버스를 열고 **하단 입력창**에 명령 |

문서·채팅의 다이어그램은 설명과 함께 읽기 좋고, 캔버스는 구조를 직접 편집하고 반복해서 개선하기 좋습니다. 문서에 삽입된 다이어그램은 확대해 살펴보고, 복사한 다이어그램을 캔버스에 붙여 넣어 편집을 이어갈 수 있습니다.

## 첫 아키텍처 그리기

탐색기의 **새 캔버스**로 시작하거나 채팅에서 저장소와 설계 범위를 지정합니다. 전체 시스템을 요청할 때는 사용자, 앱, 서버, 데이터 저장소, 외부 서비스의 경계를 함께 알려 주세요.

```text
맘마 저장소의 현재 코드를 읽고 아키텍처 캔버스를 만들어 줘.
보호자, 앱, 인증, 데이터 API, 저장소의 역할과 연결 방향을 보여 줘.
실제 코드에서 확인한 구조와 추가로 확인할 항목을 구분해 줘.
```

현재 구현을 설명할 때는 [GitHub 연결](/ko/guides/github)을 확인합니다. 새 기능을 설계할 때는 요구사항·제약·유지할 인터페이스를 적고, 현재 구조와 목표 구조를 별도 캔버스로 관리하세요.

## 하단 명령으로 함께 개선하기

캔버스를 열면 하단의 **캔버스에 명령하기…** 입력창에서 요청할 수 있습니다. AI 패널을 닫아 캔버스를 넓게 보면서 같은 대화를 이어갈 수도 있습니다. 모델 버튼에서 현재 모델을 확인하고, 원하는 변경을 입력해 전송하세요.

<Screenshot name="canvas-command" alt="맘마 아키텍처와 화면 하단의 에이전트 명령 입력창" caption="설계도를 보면서 바로 변경을 요청합니다. 화면의 입력 예시는 전송 전 상태입니다." />

```text
기존 구성요소와 연결은 유지하고,
보호자 → 앱 → 데이터 API 흐름이 읽기 쉽게 배치를 정리해 줘.
```

요청에는 **바꿀 대상, 원하는 결과, 유지할 조건**을 함께 담습니다. “계층별로 묶어 줘”, “이 화살표의 의미를 설명해 줘”, “이 구조에서 재시도 책임을 어디에 둘지 대안을 비교해 줘”처럼 설명과 변경을 번갈아 요청하며 그려 나갈 수 있습니다. 설계 대안을 그릴 때는 목표 구조라고 표시하고 현재 구현의 근거와 구분하세요.

## 선택한 부분만 집중해서 수정하기

**선택** 도구로 도형이나 연결선을 선택합니다. 여러 항목은 선택 도구로 영역을 드래그해 선택할 수 있습니다. 하단 입력창의 선택 항목 표시를 확인한 뒤 수정 내용을 적습니다. 선택 정보는 에이전트가 대상을 이해하는 참고 자료로 전달됩니다.

<Screenshot name="canvas-selection" alt="아키텍처 일부를 선택하고 하단 입력창에서 수정을 요청하는 화면" caption="선택한 항목과 유지할 주변 관계를 함께 지정하면 수정 범위가 명확해집니다." />

```text
선택한 부분의 역할을 먼저 설명해 줘.
주변 구성요소와 연결 방향은 유지하면서 라벨과 배치를 읽기 쉽게 다듬어 줘.
```

선택은 요청의 맥락을 제공합니다. “선택한 부분만 변경하고 나머지 도형과 연결은 유지해 줘”처럼 범위를 문장으로도 명시하고, 실행 후 주변 요소까지 확인하세요.

## 직접 편집하고 결과 확인하기

| 도구·동작 | 활용 방법 |
| --- | --- |
| 사각형·다이아몬드·타원 | 구성 요소와 분기 표현 |
| 화살표·선 | 호출 관계와 데이터 흐름 연결 |
| 텍스트 | 역할, 경계, 검토할 질문 작성 |
| 손 도구·확대/축소 | 큰 설계도 이동과 세부 검토 |
| 실행 취소·다시 실행 | 직접 편집한 내용을 조정 |

에이전트 작업이 끝나면 도형의 역할, 연결 방향, 기존 내용의 보존 여부와 **저장됨** 상태를 확인합니다. 검토 중에는 상단의 에이전트 편집 잠금을 활용할 수 있습니다. 저장 문제가 표시되면 저장 재시도나 초안 내보내기 안내를 따르세요.

## 설계를 구현과 연결하기

현재 구조 캔버스에 저장소를 연결하면 해당 브랜치의 push를 계기로 구조를 갱신할 수 있습니다. 목표 구조는 합의 기준으로 유지하고, [Specify MCP](/ko/mcp/connect)를 통해 코딩 에이전트가 읽도록 연결하세요.

지민이 현재 구조에서 목표 구조를 설계하고 구현으로 이어가는 예제는 [아키텍처 설계 활용 가이드](/ko/guides/architecture-design), 자동 갱신 설정은 [연결 관리](/ko/guides/automation-settings)를 참고하세요.
