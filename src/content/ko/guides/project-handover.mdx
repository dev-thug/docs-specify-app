담당자가 바뀔 때는 현재 코드의 구조와 동작을 먼저 설명하고, 기획 요청과 실제 구현의 차이를 인수인계 문서로 남기세요.

## 준비할 자료

저장소와 브랜치 또는 버전을 표시한 코드 스냅샷, 기획 메모, 기존 운영 문서를 준비합니다. 스냅샷을 사용하면 최신 저장소를 조사한 결과와 구분합니다.

## 구조와 구현 범위 확인하기

채팅으로 주요 구성요소와 의존 관계를 다이어그램으로 설명하도록 요청합니다. 기능별로 구현 확인, 기획 요청, 미확인 상태를 나누고 근거 파일을 남깁니다. 실제 운영의 권한 체계는 역할 검사 코드와 운영 정책을 함께 확인해 설명합니다.

## 다음 담당자가 이어가기

실행·테스트 순서, 알려진 제약, 남은 결정과 담당자를 문서에 정리합니다. 미구현 요청은 개선 문서로 분리하고 코딩 에이전트가 MCP로 읽게 합니다. 이후 변경을 push하면 저장소·브랜치가 연결된 기존 문서와 캔버스의 갱신 결과를 확인해 인수인계 자료를 다시 맞춥니다.

## 채팅 요청 예시

```text
이 저장소와 인수인계 메모를 읽고 현재 구조를 설명하는 문서와 다이어그램을 만들어 줘.
완료 기능, 구현 한도, 기획 요청, 미확인 항목을 근거 파일과 함께 구분해 줘.
실행·테스트 순서와 다음 담당자가 확인할 질문을 정리해 줘.
개선할 사항은 확정된 기능 설명과 분리해 줘.
```

<Note>배포·복구 절차와 운영 담당자는 실제 팀 자료로 보완합니다. 테스트 실행 기록에는 실제로 실행한 명령과 확인한 결과를 남겨 다음 담당자가 재현할 수 있게 하세요.</Note>
