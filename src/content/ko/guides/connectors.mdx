커넥터는 외부 서비스의 자료와 도구를 Specify 에이전트에 연결합니다. 서비스 계정 연결과 내가 AI에 허용하는 접근 설정은 별도로 관리합니다.

## 커넥터 열기

**도구** → **커넥터**에서 서비스와 연결 상태를 확인합니다. GitHub, Notion, Slack, Jira, Linear, Gmail, Google Calendar, Google Drive 카드를 제공합니다. Google 계열 서비스는 하나의 Google 연결을 공유합니다.

서비스 상세에서 에이전트가 읽는 데이터와 맡길 수 있는 작업을 먼저 확인합니다. 서비스마다 검색·읽기와 쓰기 작업의 범위가 다릅니다.

## 계정 연결과 AI 접근

1. 연결 관리 권한이 있는 사용자가 서비스의 **연동**을 누릅니다.
2. 서비스 화면에서 계정과 접근 범위를 허용하고 Specify로 돌아옵니다.
3. **에이전트 접근**을 켜서 에이전트가 연결된 자료와 도구를 사용할 수 있게 합니다.

계정 연결 후 자신의 AI 접근을 켜면 에이전트가 해당 서비스를 사용할 수 있습니다. 인증이 만료되면 **재연결**으로 다시 인증합니다. 관리자에게는 워크스페이스 연결 관리가, 사용자는 자신의 AI 접근 설정이 적용됩니다.

## GitHub와 Slack 범위

GitHub는 앱에 허용된 저장소만 사용할 수 있습니다. 조직 저장소는 조직 정책에 따른 승인이 필요할 수 있습니다. 문서 push 갱신은 계정 연결 후 [콘텐츠별로 설정](/ko/guides/automation-settings)합니다.

Slack의 고급 설정에서는 검색을 허용하거나 제외할 채널을 지정합니다. 둘 다 비어 있으면 공개 채널 전체가 검색 대상이며, 허용 목록이 우선합니다.

## 커스텀 MCP 서버

관리자는 커스텀 MCP 서버를 추가할 수 있습니다. HTTPS 서버 URL, 네임스페이스, 표시 이름과 인증 방식을 입력하고 필요한 시크릿을 연결 양식에 넣습니다. 서버와 도구를 확인한 뒤 신뢰 동의로 등록합니다.

도구 목록은 등록 시 고정됩니다. 서버에서 도구가 바뀌면 도구 새로고침에서 변경을 미리 보고 적용해야 합니다. 시크릿은 저장 후 다시 표시되지 않는 방식으로 보관됩니다. 갱신 시 필요한 값을 연결 양식에 다시 입력하세요.

## 사용 중단과 연결 제거

내 AI 접근을 끄면 에이전트가 해당 연결을 사용하지 않도록 할 수 있습니다. 연결을 제거하면 다시 사용할 때 재연결이 필요합니다. GitHub에 연결된 콘텐츠가 있다면 자동 갱신에도 영향을 주므로 해당 문서·캔버스의 **연결**을 확인하세요.
