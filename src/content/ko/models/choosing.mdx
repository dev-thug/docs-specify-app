일상적인 문서 작성과 수정은 **GPT-6 Luna로 시작**하세요. 기존 문서의 문장·표·여러 곳을 고치는 작업에는 **Claude Haiku 5.5도 충분히 활용할 수 있습니다**. 처음부터 상위 모델을 고르기보다, 요청한 내용이 정확히 저장됐는지와 작업 시간이 적절한지를 보고 선택하세요.

## 작업에 맞게 고르기

| 작업 | 먼저 사용할 모델 | 선택 기준 |
| --- | --- | --- |
| 제공한 자료로 짧은 문서 초안 만들기 | **GPT-6 Luna** | Luna로 초안을 만든 뒤 사실과 빠진 항목을 확인합니다. |
| 문장 바꾸기, 표 수정, 여러 문서의 지정 부분 고치기 | **GPT-6 Luna · Claude Haiku 5.5** | 수정 위치와 원하는 결과가 명확하다면 두 모델부터 사용하세요. 두 모델 모두 해당 편집 작업을 완료했습니다. |
| 짧은 편집의 대기 시간을 줄이기 | **Claude Sonnet 5.5도 비교** | 측정된 정밀 편집의 중앙값은 약 11초였습니다. 같은 요청으로 체감 속도와 사용량을 비교하세요. |
| 자료를 읽고 문서의 전체 구성을 새로 만들기 | **Luna로 시작, 필요하면 GPT-6.1 Sol과 비교** | 섹션 누락이나 설명의 연결이 부족할 때 같은 자료로 다른 결과를 받아 비교합니다. |
| 긴 자료의 해석, 복잡한 분석과 검토 | **Sonnet · Sol · Claude Opus 5.5 중 비교** | 입력할 자료의 길이, 설명의 깊이, 인용의 정확성으로 판단합니다. 모델을 바꾼 뒤에도 결과 검토는 필요합니다. |
| 다른 OpenAI 모델의 결과 확인 | **GPT-6.1 Terra** | 같은 자료와 요청으로 표현·구성·작업 시간을 비교할 때 선택할 수 있습니다. |

## 문서 작업 성능

<Note>
  현재 지원 모델은 GPT-6.1 Terra입니다. 아래 GPT-5.6 Terra 수치는 이전 모델의 측정 기록이며, GPT-6.1 Terra는 이 비교에서 측정하지 않았습니다.
</Note>

2026년 10월 문서 작업 기록을 기준으로, 같은 생성·편집 요청에서 문서 읽기·생성·수정·탐색 도구가 성공 응답을 반환한 비율과 저장 결과를 비교했습니다. 정밀 편집은 **부분 수정, 표 수정, 여러 문서의 지정 부분 수정**을 뜻합니다.

| 모델 | 문서 도구 호출 성공률 | 정밀 편집 완료율 | 편집 시간 중앙값 |
| --- | --- | --- | --- |
| GPT-6.1 Sol | 100% | 100% | 약 20초 |
| GPT-5.6 Terra | 94.1% | 100% | 약 24초 |
| GPT-6 Luna | 100% | 100% | 약 17초 |
| Claude Opus 5.5 | 100% | 100% | 약 21초 |
| Claude Sonnet 5.5 | 90.9% | 100% | 약 11초 |
| Claude Haiku 5.5 | 100% | 100% | 약 15초 |

도구 호출 성공률은 **개별 호출이 정상 처리된 비율**이고, 편집 완료율은 **저장된 문서가 요청한 수정 조건을 충족한 비율**입니다. 호출 도중 오류가 나도 후속 처리로 편집을 완료할 수 있습니다. 시간은 편집 시작부터 실행 완료까지의 관측값이며, 문서 길이·검색 범위·서버 상태에 따라 달라집니다. 이 수치는 짧은 문서 작업의 관측치이며 모든 작업의 성공률을 보장하지 않습니다.

**작은 편집에서는 Luna와 Haiku로도 요청한 결과를 얻었습니다.** 상위 모델로 바꾸는 기준은 모델 이름보다 실제 결과의 누락, 근거의 정확성, 소요 시간입니다. 새 문서를 작성할 때에는 제공하지 않은 사실이 추가되지 않았는지 확인하세요.

## 문서 자동화에 맞게 고르기

**GPT-6 Luna를 문서 자동화 기본 모델로 추천합니다.** 코드에서 문서를 새로 만들거나 push한 변경을 관련 문서에 반영할 때 먼저 선택하세요. 2026년 10월 11일 sandbox 비교에서 작은 저장소의 변경 반영 정확도는 Claude Haiku 5.5와 같았고, 큰 저장소에서는 더 많은 백엔드 함수와 화면 경로를 문서에 담았습니다.

**완료 속도가 우선이라면 Claude Haiku 5.5도 비교하세요.** 이번 측정에서는 약 2배 빨랐습니다. 다만 큰 저장소의 문서 범위와 근거를 확인하는 작업에는 Luna를 우선 권합니다.

## 문서 자동화 실측 결과

같은 조건에서 API 레퍼런스·요구사항 명세서(SRS)·아키텍처 문서를 생성하고, 값 변경·API 추가·삭제·이름 변경·연속 push가 반영되는지 확인했습니다. 별도로 파일 1,342개의 큰 저장소에서 SRS를 생성했습니다. 각 비교 조건은 모델별 1회 측정이며, 반복 측정으로 확정한 순위는 아닙니다.

| 확인 항목 | GPT-6 Luna | Claude Haiku 5.5 |
| --- | --- | --- |
| 작은 저장소의 변경 반영 | 9/9 통과 | 9/9 통과 |
| 작은 저장소 생성과 갱신 시간 | 62분 | 28분 |
| 큰 저장소 SRS 생성 시간 | 약 33분 | 약 17분 |
| 큰 저장소에서 다룬 백엔드 함수 | 13/16 | 10/16 |
| 큰 저장소에서 다룬 화면 경로 | 7/51 | 1/51 |
| 인용한 파일 경로가 실제로 존재한 수 | 156/157 | 92/95 |

큰 저장소에서는 Luna의 실행 비용도 더 낮았습니다. 다만 작은 저장소에서 Haiku의 비용을 높이던 문맥 누적 문제를 수정한 뒤에는 Haiku의 전체 비용이 기존 Luna 비교 실행보다 낮아졌습니다. 따라서 모든 작업에서 Luna가 더 저렴하다는 뜻은 아닙니다. 플랜과 요금은 [가격 안내](https://specify.app/pricing)를 확인하세요.

두 모델 모두 화면 경로를 다룬 비율은 낮았습니다. 자동화 뒤에는 **필수 기능과 화면 경로의 누락, 변경된 값, 삭제된 설명, 인용 근거**를 직접 확인하세요. 파일 경로가 존재한다는 사실만으로 설명이 정확하다고 볼 수는 없습니다. 이번 비교에는 다른 모델이 포함되지 않았으며, sandbox 결과가 운영 환경의 동일한 성능을 보장하지는 않습니다.

문서 프로젝트의 **문서 생성 모델**에서 GPT-6 Luna를 선택하세요. 설정 방법은 [문서 프로젝트 만들기](/ko/guides/doc-projects), 변경 반영 흐름은 [수정안 검토와 반영](/ko/guides/review-proposals)을 참고하세요.

## 문서 정합성 맞추기

정합성은 **문서와 코드가 맞는지**, **관련 문서끼리 같은 사실을 설명하는지**, **인용이 그 주장을 뒷받침하는지**를 함께 보는 기준입니다. 도구가 정상 실행됐거나 문서가 저장됐다는 것과 별도로 확인합니다.

| 확인 대상 | 좋은 결과의 기준 |
| --- | --- |
| **기본값·정책·한도** | 개요, API 레퍼런스, 운영 문서가 현재 코드의 같은 값을 설명합니다. |
| **삭제된 기능** | 현재 기능처럼 남은 설명·예시·링크가 없고, 필요한 변경 안내가 있습니다. |
| **이름과 경로** | 저장된 문서 제목, 본문 제목, 소스 링크가 같은 현재 이름을 사용합니다. |
| **요청·응답·오류** | 코드와 테스트에서 확인한 동작이 설명 및 예시와 일치합니다. |
| **인용 근거** | 경로와 줄 번호가 맞는 데 더해, 실제 원문이 문장의 주장을 뒷받침합니다. |
| **기존 팀 설명** | 코드 변경과 무관한 수동 작성 내용과 운영 설명은 유지됩니다. |

정합성을 맞출 때는 **변경 사실과 확인할 문서 목록을 함께 지정**하세요. 예를 들어 “기본 limit 변경을 개요·API 레퍼런스·운영 가이드에서 대조하고, 서로 다른 값과 근거가 없는 설명을 정리해 줘”처럼 요청합니다. 먼저 Luna·Haiku로 범위가 명확한 수정을 수행하고, 자료 해석이나 문서 전체 연결이 부족할 때 다른 모델과 비교하세요. 최종 선택 기준은 모델 등급보다 **빠진 변경이 없는지와 근거가 맞는지**입니다.

## 모델을 바꿀 때

- **원하는 부분을 고치지 못했다면** 문서와 수정 위치를 지정하고, 바꿀 내용과 유지할 내용을 나누어 요청하세요. 그래도 결과가 부족하면 같은 요청으로 다른 모델을 비교합니다.
- **긴 문서의 구성이 부족하다면** 먼저 목차와 필수 항목을 정한 뒤 섹션별로 작성하게 하세요. 설명의 연결이나 분석이 부족할 때 Sonnet·Sol·Opus의 결과를 비교합니다.
- **코드 변경을 여러 문서에 반영한다면** 개요·레퍼런스·운영 문서의 값과 예시를 함께 확인하세요. 큰 모델도 전체 반영을 보장하지는 않습니다.
- **출처가 중요한 문서라면** 모델의 답변과 인용 원문을 대조하세요. 링크가 열리는지뿐 아니라 실제 설명을 뒷받침하는지 확인합니다.

## 사고 강도 고르기

짧은 초안과 지정 부분 수정은 **끄기** 또는 지원되는 낮은 단계에서 시작하세요. 여러 자료를 비교하거나 설명을 깊게 다뤄야 할 때 강도를 높여 결과를 비교합니다. 강도를 높이면 사용량과 시간이 늘 수 있습니다. 무료 플랜에서는 **끄기**로 고정됩니다.
