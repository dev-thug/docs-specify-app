모델을 고르기 어렵다면 **기본 모델인 GPT-6 Luna로 시작**하고, 같은 자료와 요청으로 결과를 비교하세요. 최신 평가에서는 작은 편집을 여러 모델이 수행했지만, 자동 갱신 누락과 인용 오류는 고성능 모델에서도 관측됐습니다. 모델을 바꾸는 것만으로 문서 품질이 보장되지는 않습니다.

## 작업별 선택 기준

| 하려는 일 | 시작점 | 결과를 확인할 기준 |
| --- | --- | --- |
| 짧은 질문, 요약, 작은 문서 편집 | GPT-6 Luna | 원문과 결과를 대조하고, 요청하지 않은 사실이 추가되지 않았는지 확인합니다. |
| 다른 모델로 같은 작업 비교 | GPT-6.1 Sol 또는 Claude Sonnet 5.5 | 같은 입력과 수정 범위로 비교합니다. 이번 평가만으로 우위를 확정할 수 없습니다. |
| 여러 문서 생성·자동 갱신 | 문서 생성 모델 설정으로 선택 | 개요·레퍼런스·정책 문서를 모두 다시 읽고 값과 근거를 대조합니다. |
| 긴 문서 검토와 복잡한 분석 | 필요한 경우 Claude Opus 5.5도 비교 | Opus에서도 누락과 인용 오류가 관측됐으므로 별도 검토가 필요합니다. |

## 최신 내부 평가 결과

**2026년 10월 9일**, localhost와 Amplify sandbox에서 현행 모델 6종을 실제 앱으로 평가했습니다. 합성 API 저장소와 고정 문서를 사용해 문서 생성, 부분·표·다중 문서 편집, 소스 질의, API·위키 생성, push에 따른 수정·추가·삭제·이름 변경·무관 변경·연속 변경을 검사했습니다. production에서 수행한 테스트가 아닙니다.

72개 논리적 시도 중 메모리·검색 자료 혼입 또는 준비 오류가 있었던 26개를 제외했습니다. 비교 가능한 **46개에서 핵심 작업 PASS 35개, FAIL 11개**를 기록했습니다. 연속 push의 두 실행은 하나의 논리적 테스트로 집계했습니다.

| 모델 | 유효 테스트 | 작업 통과 / 실패 | 근거 통과 / 검토 |
| --- | --- | --- | --- |
| Claude Haiku 5.5 | 7 | 5 / 2 | 1 / 2 |
| Claude Opus 5.5 | 11 | 7 / 4 | 2 / 6 |
| Claude Sonnet 5.5 | 11 | 7 / 4 | 0 / 6 |
| GPT-5.6 Terra | 6 | 6 / 0 | 0 / 2 |
| GPT-6 Luna | 6 | 5 / 1 | 0 / 2 |
| GPT-6.1 Sol | 5 | 5 / 0 | 1 / 1 |

**핵심 PASS**는 저장된 결과가 해당 작업의 핵심 조건을 충족했다는 뜻입니다. **의미 근거 통과**는 인용한 코드·문서가 실제 주장을 뒷받침했는지 별도로 검토한 결과입니다. 핵심 작업이 PASS여도 인용 의미는 틀릴 수 있으며, 근거를 검토하지 않은 테스트는 이 열의 분모에 포함하지 않습니다.

- 같은 구성으로 수행한 단순 생성·편집 24개는 23개가 핵심 PASS였습니다. 실패한 생성에는 제공하지 않은 공유·권한 주장이 추가됐습니다.
- 이 중 부분·표·다중 문서 정밀 편집은 18개 모두 핵심 PASS였습니다. 모델별 한 번씩 수행한 합성 문서 테스트 결과입니다.
- 나머지 소스 질의·자동화 22개는 모델별 구성과 분모가 달라 단순 성공률 비교에 적합하지 않습니다.

<Note>
  계획한 198개 중 152개는 완료하지 못했고, 2·3회차 반복도 수행하지 않았습니다. 모델별 표본 수가 다르므로 최종 순위, 반복 안정성, p95 지연시간, 성공당 비용 우위를 주장할 수 없습니다. 사고 강도별 비교, 현행 모델의 스킬·커넥터 전반 성능도 이 평가로 확정하지 않았습니다.
</Note>

## 이전 평가와 구분하기

2026년 7월의 38개 시나리오 베이스라인은 Claude Haiku 4.5와 Claude Sonnet 4.6을 비교한 자료입니다. 현행 모델과 테스트·판정 조건이 다르므로 최신 결과와 합산하거나, 이전 세대의 성공률·평가자 점수·비용 배수를 현행 모델 추천으로 이어 쓰지 않습니다.

## 문서 결과를 검토하는 방법

1. 변경된 기본값·정책·엔드포인트가 **관련된 모든 문서**에 반영됐는지 확인합니다. 완료 표시만으로 전체 갱신을 판단하지 마세요.
2. 인용 경로와 줄 번호가 존재하는지에 더해, 해당 코드가 문장의 주장을 실제로 뒷받침하는지 확인합니다.
3. 삭제·이름 변경 후 본문, 저장된 문서 제목, 소스 경로, 예시가 일치하는지 확인합니다.
4. 도구 오류나 읽지 못한 범위가 있었다면 미확인 내용을 남기고 검토합니다. 모델의 완료 답변만으로 정확성을 판단하지 마세요.

평가에서 관측된 문제와 개선 제안은 수정·배포 완료를 뜻하지 않습니다. 자세한 검토 흐름은 [수정안 검토와 반영](/ko/guides/review-proposals)을 참고하세요.

## 사고 강도 고르기

짧은 질문과 작은 수정은 지원되는 낮은 단계에서 시작하고, 결과가 부족할 때 강도를 조절하세요. 높은 강도는 더 많은 사용량과 시간을 쓸 수 있으며 정확성을 보장하지 않습니다. 무료 플랜에서는 **끄기**로 고정되고, 모델별 지원 단계는 [모델 개요](/ko/models/overview)에서 확인할 수 있습니다.
