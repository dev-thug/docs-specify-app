Specify 제품과 문서에서 자주 쓰는 용어입니다.

| 용어 | 뜻 |
| --- | --- |
| **워크스페이스** | 팀이 문서·대화·결정·코드 기록과 멤버, 연결 도구를 공유하는 단위. 데이터가 격리되는 경계입니다. |
| **노드** | 워크스페이스의 핵심 콘텐츠 단위. 문서, 폴더, 에이전트 규칙이 모두 노드입니다. |
| **문서 프로젝트** | GitHub 저장소를 근거로 개발문서를 만들고 유지하는 단위. 폴더, 소스, 스킬, 자동화 설정을 묶습니다. |
| **소스** | 문서 프로젝트가 근거로 삼는 GitHub 저장소와 브랜치. |
| **문서 스킬** | 에이전트가 문서를 생성할 때 따르는 작성 규율. |
| **보조 스킬** | 문서 스킬을 돕는 참고 절차. 최대 5개까지 선택할 수 있습니다. |
| **증분 갱신** | 코드 변경분만 반영해 문서를 갱신하는 방식. 자동 갱신을 지원합니다. |
| **전체 재생성** | 매번 문서 전체를 다시 만드는 방식. 자동 갱신을 지원하지 않습니다. |
| **수정안** | 코드 변경에 맞춰 문서를 고치자는 제안. 변경 근거와 수정 전후를 담습니다. |
| **push 시 실행** | 소스 브랜치에 코드가 올라올 때 문서 수정안을 준비하는 트리거. |
| **스타일 가이드** | 문서에 적용할 마크다운 작성 규칙. 프로젝트 가이드가 워크스페이스 가이드보다 우선합니다. |
| **인박스** | 백그라운드 작업의 진행 상황과 결과가 모이는 곳. |
| **스레드** | 에이전트와 나누는 대화 단위. |
| **데일리 브리핑** | 워크스페이스 변경, 문서 노후화 알림, 추천 작업을 모은 일일 요약. |
| **RAG** | 검색 증강 생성. AI가 답하거나 문서를 쓰기 전에 워크스페이스 자료를 검색해 근거로 삼는 방식. [워크스페이스 RAG](/ko/knowledge/rag) 참고. |
| **색인** | RAG 검색을 위해 문서와 파일을 조각(청크)으로 나누어 저장하는 과정. 문서를 고치거나 파일을 올리면 다시 색인됩니다. |
| **표준 문서 라이브러리** | IEC 62304, ISO 14971 같은 표준을 조항 단위로 검색하는 지식 소스. [표준 문서 라이브러리](/ko/knowledge/standards) 참고. |
| **[GAP]** | 표준이나 자료로 뒷받침되지 않는 내용에 에이전트가 붙이는 표시. 사람이 확인해야 합니다. |
| **사고 강도** | 모델이 답하기 전에 추론하는 깊이. 끄기, 낮음, 보통, 높음, 엑스트라, 최대 중에서 고릅니다. |
| **커넥터** | GitHub, Notion, Slack 같은 외부 서비스를 연결해 에이전트가 읽고 작업할 수 있게 하는 연동. |
| **플러그인** | 스킬 여러 개를 묶어 한 번에 설치하는 패키지. 예: medical-device-docs. |
| **자동화** | 정해진 일정에 에이전트가 프롬프트를 실행하도록 만든 루틴. |
| **MCP** | Model Context Protocol. AI 에이전트를 외부 도구·데이터에 연결하는 개방형 표준. |
| **Specify MCP** | Claude Code·Codex 등 외부 코딩 에이전트에 워크스페이스 맥락을 제공하는 MCP 서버. |
| **MCP 토큰** | 외부 에디터가 Specify MCP에 인증할 때 쓰는 워크스페이스 단위 토큰. 기본 권한은 읽기 전용입니다. |
