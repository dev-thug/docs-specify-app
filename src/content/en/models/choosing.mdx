If you are unsure which model to choose, **start with GPT-6 Luna, the default model**, and compare results using the same sources and request. Several models handled small edits in the latest evaluation, but high-end models also missed document updates and made citation errors. Changing the model alone does not guarantee document quality.

## Choosing by task

| Task | Starting point | What to check |
| --- | --- | --- |
| Short questions, summaries, small document edits | GPT-6 Luna | Compare the result with the source and check for unsupported additions. |
| Compare the same task with another model | GPT-6.1 Sol or Claude Sonnet 5.5 | Use the same input and edit scope. This evaluation does not establish a winner. |
| Generate or automatically update several documents | Choose through Doc Generation Model settings | Reread the overview, reference, and policy documents and compare values and evidence. |
| Review long documents or analyze complex issues | Compare Claude Opus 5.5 when needed | Opus also missed updates and made citation errors, so separate review is necessary. |
| Use Claude Haiku 5.5 or GPT-5.6 Terra | Available in the model menu | Note the **Not recommended** badge. Do not interpret this evaluation as a model ranking. |

## Latest internal evaluation

On **October 9, 2026**, six current models were evaluated in the actual app on localhost and an Amplify sandbox. A synthetic API repository and fixed documents covered generation, partial, table, and multi-document edits, source questions, API and wiki generation, and push-driven modifications, additions, deletions, renames, unrelated changes, and consecutive changes. These were not production tests.

Of 72 logical attempts, 26 were excluded because of memory or search-input contamination or preparation errors. The **46 comparable tests recorded 35 core task PASS results and 11 FAIL results**. The two runs for consecutive pushes were counted as one logical test.

| Model | Valid tests | Task PASS / FAIL | Evidence passed / reviewed |
| --- | --- | --- | --- |
| Claude Haiku 5.5 | 7 | 5 / 2 | 1 / 2 |
| Claude Opus 5.5 | 11 | 7 / 4 | 2 / 6 |
| Claude Sonnet 5.5 | 11 | 7 / 4 | 0 / 6 |
| GPT-5.6 Terra | 6 | 6 / 0 | 0 / 2 |
| GPT-6 Luna | 6 | 5 / 1 | 0 / 2 |
| GPT-6.1 Sol | 5 | 5 / 0 | 1 / 1 |

**Core PASS** means the saved result met the task's core conditions. **Semantic evidence passed** is a separate check of whether cited code or documents supported the actual claim. A core task can pass while its citations are semantically wrong. Tests without evidence review are not included in that column's denominator.

- Of 24 simple generation and editing tests with matching task coverage, 23 passed the core task. The failed generation added unsupported sharing and permission claims.
- Within those tests, all 18 precise partial, table, and multi-document edits passed the core task. Each model performed each synthetic document test once.
- The remaining 22 source-question and automation tests had different task coverage and denominators across models, so simple success-rate comparisons are inappropriate.

<Note>
  Of 198 planned tests, 152 were not completed, and second and third repetitions were not performed. Unequal model samples do not support claims about final rankings, repeatability, p95 latency, or cost per successful task. This evaluation also did not establish comparisons by reasoning effort or overall skill and connector performance for current models.
</Note>

## Separating earlier evaluations

The July 2026 baseline of 38 scenarios compared Claude Haiku 4.5 with Claude Sonnet 4.6. Its models, tests, and assessment conditions differ from the latest evaluation. Do not combine the results or carry previous-generation success rates, judge scores, or cost ratios into recommendations for current models.

## Reviewing document results

1. Check that changed defaults, policies, and endpoints appear in **every affected document**. A completion indicator alone does not establish full coverage.
2. Check both that a citation path and line range exist and that the cited code supports the sentence's actual claim.
3. After deletion or renaming, compare the body, saved document title, source paths, and examples.
4. If tools failed or some content could not be read, record and review what remains unverified. A model's completion message does not establish accuracy.

Observed issues and proposed improvements in the evaluation do not mean fixes have been implemented or deployed. See [Review and apply proposed updates](/en/guides/review-proposals) for the review workflow.

## Choosing reasoning effort

Start short questions and small edits at a supported low level, then adjust if the result is insufficient. Higher effort can use more time and budget without guaranteeing accuracy. The Free plan fixes effort at **Off**. See [Models overview](/en/models/overview) for supported levels.

## Setting workspace defaults

Automations and document generation use workspace model settings separately from chat.
