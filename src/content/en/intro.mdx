## Understand and review code through diagrams

Ask for architecture, feature flows, and API behavior grounded in the repository, then read the results. Compare the structure and behavior with your intended design and requirements.

<Screenshot name="architecture-document" alt="Specify project document explaining repository structure and processing flow" caption="Read feature explanations alongside source paths to check the implementation." />

1. **Understand** — Connect a repository and create a project overview and behavior documentation.
2. **Review** — Read documents and canvases to check dependency directions and feature flows against requirements.
3. **Improve** — Use chat to record improvements in a document your coding agent can read through MCP.
4. **Check again** — After the next change, inspect updates to documents and canvases linked to the repository.

<Note>Automatic repository updates apply to **documents and canvases linked to that repository**. The agent edits and saves the content directly. Review the edit history and saved result after completion.</Note>

## Prepare certification documents

Certification documents start from the same evidence. Collect product overviews, requirements, designs, and test material; distinguish confirmed facts from missing evidence when drafting. The [certification document guide](/en/guides/medical-device-docs) explains what to prepare and review.

See [Specify Certify](https://certify.specify.app) for supported areas and expert review needs. Complete submission material through expert review, and establish certification and conformity through the applicable assessment process.

## Give your agent the same context

Let your coding agent find and read the improvement document directly. Connect [Specify MCP](/en/mcp/overview) and ask your coding agent: “Read the improvement document in Specify and update the implementation accordingly.” See [MCP tools](/en/mcp/tools) for search, reading, and permitted writing tools.
