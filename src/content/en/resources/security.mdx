Check access scope and permissions when managing workspace material and external tool connections.

## Workspace and roles

Material access is evaluated against the current workspace, membership, and role. Confirm the intended workspace when switching between them. See [Team invitations and permissions](/en/workspace/members) for roles.

## External service connections

Connected services such as GitHub, Notion, and Slack use the authorized accounts and resources. External material is searched through connectors rather than copied into the workspace knowledge index. Disconnect services you no longer need and review permissions in the source service too.

## MCP access

External clients authenticate using an MCP token or OAuth. Access is read-only by default; writes require a separate scope and an appropriate workspace role. Do not store tokens in shared documents or repositories.

Documents and folders excluded from MCP, including their descendants, are excluded from external agent access. Administrators can manage external access and tool policies. See [Tokens and access policies](/en/mcp/access).
