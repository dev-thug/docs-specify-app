After an automatic update, check the run result alongside the saved document or canvas. Push-triggered work edits linked content directly. Use change history and undo to inspect or reverse the result.

## How an update runs

1. A push arrives on the branch linked to the content.
2. The agent compares the diff, the current branch source, and the existing content.
3. It updates the existing document or canvas when relevant facts have changed. It can preserve the existing content when relevant information is already current.

With consecutive pushes, a newer run may replace an earlier one. Check that the result reflects the latest source state.

## Open the run result

Open **Connections** on the content to check the repository and branch, then select **Run history** to open the inbox. Check the run’s analysis coverage, follow-up items, and saved updates. If it reports unread files or tool errors, review those areas next.

## Review the content

- Check changed values, feature names, and API examples against the current code.
- Compare documents and canvases for consistent components and data flows.
- Confirm that unrelated explanations and human-written content were preserved.
- Leave unread source areas marked as unverified and request further analysis.

## Undo or pause updates

Check document history and undo changes when needed. Use the agent editing lock while people refine content. People can continue editing while automatic updates are paused.

To stop reflecting future pushes, uncheck the repository under **Manage connections** → **Event connections**. See [Manage connections](/en/guides/automation-settings).
