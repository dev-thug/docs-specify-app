AI in your IDE knows the code itself well, but it doesn't know why it was built that way. Specify's AI answers based on the docs, conversations, decisions, and code history collected in your workspace.

## Questions it answers well

| Question type | Example |
| --- | --- |
| **Why** | "Why did we move payment retries into a queue?" |
| **Where** | "Where is the logic that saves notification settings?" |
| **How** | "What order do we work in when adding a new API endpoint?" |
| **Status** | "Did anything change around authentication this week?" |

## Get better answers

- **Narrow the scope.** Including a service name, feature name, or time period makes it easier to find evidence.
- **Check the evidence.** Before relying on an answer for an important decision, check the docs and code it was based on yourself.
- **Save answers as docs.** Writing up answers to recurring questions gives the next question something to draw on.

<Note>
  AI uses only the docs your workspace permissions allow as evidence. Content from docs you don't have access to isn't included in answers.
</Note>

## Use with non-developer colleagues

Colleagues who find technical docs hard to read can ask in everyday language and still get answers they understand. Asking something like "What changes will customers see in this release?" lets them understand where the project stands without pulling in the development team.
