Automatic updates use the repositories linked to each document or canvas. Check the connections and branches under **Connections**. The content owner manages these settings.

## Link or unlink a repository

1. Open the document or canvas.
2. Open **Connections** → **Manage connections** → **Event connections**. You can also use **Event connections** in the content menu.
3. Check a repository to link it. Uncheck it to stop future push updates from that repository.

The list shows each repository and branch. New connections use the repository's default branch. You can link multiple repositories; configure documents and canvases individually.

## Read the connection status

**Connections** shows repositories, linked branches, and GitHub connection status. Use the refresh action to check again.

- Reconnect GitHub in the workspace if the connection was removed.
- Restore a suspended app installation on GitHub.
- Refresh an unknown status, then check access permissions.

An active GitHub connection still requires the owner's GitHub usage setting, repository access, and content write permission for updates to run.

## Agent editing lock

Use the agent editing lock to pause automatic updates while people refine the content. Unlock it to allow updates again. Check the inbox for subsequent execution results.

## Update scope and results

The agent reads the existing linked content and changes relevant source-supported facts. It is instructed to preserve the document's language, purpose, unrelated sections, and protected content. Canvas updates likewise use existing objects and layout.

Open **Run history** and [review automatic updates](/en/guides/review-proposals).
