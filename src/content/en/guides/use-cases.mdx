## A shared workflow

1. **Understand the current state.** Choose the repository, reference branch, and source documents. Ask in chat for architecture diagrams and feature explanations.
2. **Review as a person.** Compare unexpected structure, edge cases, and components that appear to share a role against source code.
3. **Agree in an improvement document.** Record the reason, scope, acceptance criteria, and open questions.
4. **Let the coding agent read it.** Ask Claude Code or Codex to read the improvement document through Specify MCP, then implement and test.
5. **Review again after changes.** Compare linked documents and canvases updated after the push with the current code and continue the review.

<Note>When components look similar, a person checks the source to decide whether to reuse or consolidate them. Repository-linked documents and canvases update directly, so review the saved result and edit history afterward.</Note>

## When you need certification preparation

Create and manage drafts in Specify and select specialist help where needed. Check the relevant fields and scope at [Specify certification support](https://certify.specify.app). Document preparation and certification decisions are separate.
